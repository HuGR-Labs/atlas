I

Why rebuildThe v1 failure was structural, not cosmetic.

In Maestro v1 a single blurred "lead" invented the product, the spec, the architecture, the decomposition, and drove execution — all at once, all implicit.

That is exactly why the dream product was mostly missing or sloppy: nobody owned defining it. Product and architecture were never ratified, never navigable, invented on the fly. The seats were one or two .md files pretending to be a team.

Orchestra fixes the root cause, not the symptom. It makes defining and designing first-class, owned phases with a hard handoff — and it makes every seat a real harness (its own CLI, MCP tools, skills, and Agent-SDK loop), built in its own repo, then vendored into one mono. The .md stops being the seat; it becomes the thin adapter a host uses to invoke the seat.

The reframe v1's bar was “a mechanism fires and a test is green.” That is not the dream product. Orchestra's bar is craft: each discipline owned, each seam frozen, each guarantee falsifiable. Design-first — zero product code ships until this is ratified.
II

Grounded in the 2026 state of the artThe design isn't taste — it's what the research forces.

The cost center
The supervisor's context

Multi-agent systems burn ~15× the tokens of a chat (a lone agent ~4×), and token usage alone explains 80% of performance variance. The lead's context is the budget. 1

The structural answer
The return-firewall

Subagents run in isolated context windows; only the final message returns. Orchestra makes that a contract — the seat returns a ResultCard, never a transcript. 2

The topology
Orchestrator-worker + evaluator

Orchestrator-worker is ~70% of production deployments; the evaluator-optimizer pair (structured scoring, not free critique) is the proven quality loop — our GAN. 3

The failure modes
What kills naïve fan-out

Anthropic's real bugs: “spawning 50 subagents for simple queries,” seats duplicating each other's work. → atom-only dispatch, disjoint slicing, a cap of ~6–8. 1

The SDK triad we build on The Claude Agent SDK names the exact separation Orchestra needs: Skill teaches the how · Hook enforces the rule · Subagent isolates the work. A seat is all three at once — its kit & skills, the governance hooks, and its own isolated loop. 2
III

The score: six phases, one directionWork flows down. Nothing skips a phase. The Conductor never invents.

The load-bearing separation: orchestration is a different discipline from definition and design. The Conductor receives a ratified spec + architecture and turns it into merged, verified, sealed work. When the plan is under-decided, it bounces up — it never fills the gap by guessing. That single rule is the whole anti-hallucination stance.

V

The Conductor's three actsAll judgment lives in Act I. After that, the seats only transcribe.

Decompose

  • Slice disjoint. Each WP owns a non-overlapping write-scope. The shared file every WP would touch is eliminated from the edit path — the Conductor owns it.
  • Freeze the contract at every seam; hand each seat anchor code to transcribe — never “design the interface.”
  • The four axioms per WP: completeness · invariants · qualityBar · DoD. Miss one → it does not type-dispatch.
  • Build the merge DAG — a merge order, never a dispatch barrier.

Dispatch

  • Chew the brief. The WorkBrief is the only channel to the seat — pre-digested, minimal, no dumping.
  • Arm the relay. relayToken = sha256(brief) — content-addressed; a seat can't release a tampered chain.
  • Route by roster. Generators get build WPs; evaluators get verify WPs; never crossed.
  • The return-firewall. The seat returns a ResultCard and nothing larger — this is why context doesn't explode at scale.

Integrate

  • Cold-check the card. Gate results are measured exit codes; changed files read from git — never a self-report.
  • GAN gate. A generator WP is not sealable until an evaluator returns a passing card (scored by dimension).
  • Merge in DAG order under a change-scoped gate; out-of-scope writes are held.
  • Absorb + meter. Grounded memory facts persist; real token cost feeds the ROI ledger.

Each seat is built in its own repo (one session per seat), against the frozen @orchestra/contracts seam, then vendored in under seats/<id>/ via git subtree. VII

The keystone seamOne frozen interface. Freeze it before any seat is built.

This is the single contract that lets the Conductor drive any seat uniformly, and lets every seat be built in its own repo, blind to the others. A seat repo depends on this and nothing else from the mono.

// @orchestra/contracts — the one channel in, the one channel out.

interface WorkBrief {           // the chewed dispatch packet — the ONLY channel lead→seat
  wpId: string
  anchor: string             // the target, MARKED — the seat transcribes, never designs
  owns: string[]             // the disjoint write-scope (no two seats overlap)
  contract: WpContract       // the four axioms — REQUIRED, or it won't type-dispatch
  gates: Gate[]              // real completion oracles — exit 0 = green
  relayToken: string         // sha256(brief) — content-addressed arm↔release
  returnShape: ResultShape
}

interface ResultCard {          // the return-firewall — the lead ingests THIS, never a transcript
  wpId: string
  outcome: 'sealed' | 'held' | 'blocked' | 'escalated'
  evidence: Evidence         // measured exit codes + git-read changed files + real tokens
  fields: Record<string, string>
  note: string               // ≤ returnShape.maxNoteChars — the compact human line
}

interface SeatHarness {         // every seat satisfies exactly this; its whole world lives behind run()
  manifest(): SeatManifest
  run(brief: WorkBrief, ctx: SeatRunContext): Promise<ResultCard>
}
